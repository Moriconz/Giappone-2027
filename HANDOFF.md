## Cos'è l'app
**Tabi** — travel planner PWA (vanilla JS, no framework, no bundler) con layer gluten-free opzionale. Planner **globale**, non solo Giappone; il trip Giappone 2027 è il caso d'uso di partenza. ## Decisioni chiave
- **`_escJs` ≠ `_esc`**: per valori interpolati dentro `onclick="fn('...')"` serve escape JS-string (backslash poi apice) *seguito da* escape HTML normale sopra — non uno dei due da solo. Pattern da riusare se si trovano altri `onclick="...('${_esc(...)}'"` in giro.
- **`window.sanitizeAvatarUrl()`** in `ui-helpers.js` è ora il punto centrale per qualunque avatar/URL immagine che arriva da un peer — usarlo sempre invece di reimplementare un controllo di schema locale.
- Il flusso "Partecipare a un viaggio" ora punta a "Gruppo → Entra Esistente" (già esistente) invece di costruire un join-flow nuovo — se in futuro serve un'esperienza di join dedicata, questa è la base da estendere, non da duplicare.

## Vincoli e convenzioni
- Script IIFE browser, `<script defer>` in index.html; niente ES modules/bundler.
- MAI sed/perl multi-riga greedy: Edit manuale + `node --check` + smoke test dopo ogni modifica.
- Verifica sempre: `python3 -m http.server PORT` + `node smoke-test.mjs http://localhost:PORT` (exit 0 obbligatorio) + `node scripts/lint-i18n.mjs` se si toccano stringhe. Per bug UI, verifica nel browser reale a viewport mobile (375×812), non solo lo smoke test — v3.45 ha trovato bug (overlap widget meteo, XSS visive) invisibili al solo smoke test.
- Il Service Worker cachea aggressivamente: durante test manuali nel browser, disinstallarlo (`navigator.serviceWorker.getRegistrations()` + `unregister()` + `caches.delete()`) prima di verificare un fix, altrimenti si testa codice vecchio.
- Lo stato app vive TUTTO in un unico blob `localStorage['giappone2027_state_v1']` (vedi `js/state.js`), non in chiavi separate — per seedare dati di test, mutare `window.state.X` e chiamare `window.saveState()`, non `localStorage.setItem('X', ...)` diretto (eccetto `tripProfile`, che ha anche una copia flat separata usata solo come marcatore di completamento onboarding).
- Commit in italiano, CHANGELOG.md aggiornato ad ogni versione, push su `main` + sync cartella deploy sempre (quando i permessi lo consentono).
- Nuovi bottoni-layout (dentro card con bordo proprio): classe `btn-plain`. Se il bottone usa `background:linear-gradient(...)` inline, il vecchio override glassmorphism intercettava quella sottostringa — ora l'override è morto (vedi Prossimi step #4) ma il pattern era `background-image:` per evitarlo, se mai riappare un problema simile altrove.
- Nuove stringhe UI: sempre `T('namespace.chiave', 'fallback italiano')` + chiavi in `js/i18n.js` per it/en/ja, mai testo nudo.
- HTML generato via template string con `onclick="..."` inline: qualunque valore interpolato lì dentro che può contenere un apice (nomi POI da OSM, id da peer MQTT, testo utente) va passato attraverso un escape JS-string-poi-HTML (vedi Decisioni chiave), non il normale `_esc()` per testo visibile.
- Prima di un refactor/feature grossa: cercare worktree isolate in `.claude/worktrees/` o branch `claude/*` — possono contenere lavoro preparato in sessioni precedenti (ma verificare quanto sono indietro rispetto a `main` prima di fidarsi: in questa sessione le worktree trovate erano 16-42 commit indietro, inutilizzabili).
